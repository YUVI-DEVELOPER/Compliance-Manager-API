# Audit Review Step 11: Optional AI Executive Summary + CAPA Recommendation

## Scope

Step 11 adds an optional reviewer-support narrative for Veeva Audit Trail Periodic Review reports. The AI output is stored separately from the deterministic report and can generate:

- Executive summary
- Risk statement
- Key observations
- CAPA recommendation wording suggestions
- Stakeholder summary
- Reviewer notes suggestion

The deterministic 10-point checklist, score rows, findings, approval workflow, PDF content, scheduler, and notifications remain the source of truth.

## Configuration

The service reuses the existing OpenAI-compatible LLM configuration used elsewhere in the API:

- `LLM_ENABLED`
- `LLM_API_KEY`
- `LLM_MODEL`
- `LLM_BASE_URL`
- `LLM_TIMEOUT_SECONDS`
- `LLM_MAX_RETRIES`

If AI is disabled or missing required configuration, `POST /audit-review-reports/{report_id}/generate-ai-summary` returns a controlled error with `success: false` and `data.ai_configured: false`. Normal audit review workflows continue to work.

## Data Sent To AI

The AI service builds a sanitized structured input containing:

- Asset ID, asset code, and asset name
- Report ID and job ID
- Review period
- Veeva instance name and app name
- Audit trail type and trigger mode
- Total records reviewed
- Overall deterministic score and rating
- Finding counts by severity
- Score breakdown for the 10 deterministic checks
- Top findings from safe report summaries
- Deterministic recommendation text already generated by the system
- Report status and approval metadata
- Reviewer comments, if available

## Data Not Sent To AI

The AI service does not send:

- `raw_payload_json`
- Full Veeva raw API responses
- Veeva credentials
- Session IDs
- Authorization headers
- Tokens
- Secret environment variables
- Private system logs

The sanitizer removes forbidden keys such as raw payload, authorization, token, password, secret, session, API key, and credential fields before the prompt is built.

## Prompt Guardrails

The system prompt instructs the model:

- Generate reviewer-support narrative only.
- Use only the provided structured data.
- Do not change the compliance score.
- Do not change the rating.
- Do not invent findings.
- Do not invent regulatory violations.
- Do not claim final QA approval.
- Do not say remediation was completed.
- CAPA recommendations are suggestions only.
- Human QA/Compliance review remains authoritative.
- If evidence is insufficient, state that reviewer confirmation is required.

The expected AI JSON shape is:

```json
{
  "executive_summary": "string",
  "risk_statement": "string",
  "key_observations": ["string"],
  "capa_recommendations": [
    {
      "title": "string",
      "description": "string",
      "suggested_owner": "string",
      "suggested_due_days": 30,
      "priority": "LOW / MEDIUM / HIGH / CRITICAL"
    }
  ],
  "stakeholder_summary": "string",
  "reviewer_notes_suggestion": "string",
  "limitations": [
    "AI did not review raw audit payload.",
    "Deterministic checks and human QA review remain authoritative."
  ]
}
```

The generated Markdown begins with this disclaimer:

> AI-generated narrative for reviewer support only. Deterministic checks, score, findings, and QA approval remain authoritative.

## Storage

AI output is stored on `audit_review_report` in separate nullable fields:

- `ai_summary_json`
- `ai_summary_markdown`
- `ai_generation_status`
- `ai_generated_by`
- `ai_generated_dt`
- `ai_model_name`
- `ai_error_message`

Statuses are:

- `NOT_REQUESTED`
- `GENERATING`
- `GENERATED`
- `FAILED`

The service never overwrites `report_payload_json`, `report_markdown`, score rows, findings, report status, or approval decision data.

## Endpoints

### Generate AI Summary

`POST /audit-review-reports/{report_id}/generate-ai-summary`

```json
{
  "requested_by": "qa.manager@example.com",
  "summary_style": "executive",
  "include_capa_recommendations": true
}
```

Allowed report statuses: `DRAFT`, `UNDER_REVIEW`, `APPROVED`, `REJECTED`, `SUPERSEDED`.

### Get AI Summary

`GET /audit-review-reports/{report_id}/ai-summary`

Returns the stored AI summary, or a controlled `NOT_REQUESTED` response when no AI summary has been generated.

### Clear AI Summary

`DELETE /audit-review-reports/{report_id}/ai-summary`

Clears only the stored AI narrative fields and resets the AI generation status to `NOT_REQUESTED`. It does not change the deterministic report, score, rating, findings, report status, approval metadata, scheduler jobs, notifications, or PDF content.

## UI Behavior

The report view includes an `AI-Assisted Summary` panel that:

- Shows a warning that deterministic checks and QA review remain authoritative.
- Lets the reviewer generate or regenerate an AI summary.
- Lets the reviewer clear the stored AI summary before regenerating from scratch.
- Shows generated timestamp and model name.
- Displays AI Markdown in a separate readable block.
- Shows controlled errors when AI is unavailable.
- Does not expose raw payload.
- Does not provide approval, rejection, notification, scheduler, or score-changing controls.

AI text is not automatically injected into the formal report PDF or approved report.

## Testing

1. Run the normal flow: Create Job -> Extract -> Analyze -> Generate Report.
2. Call `GET /audit-review-reports/{report_id}` and note `status`, `overall_score`, and `rating`.
3. Call `POST /audit-review-reports/{report_id}/generate-ai-summary`.
4. Confirm `data.status` is `GENERATED` when AI is configured.
5. Confirm `ai_summary_json` and `ai_summary_markdown` are present.
6. Confirm the response does not include `raw_payload_json`, session IDs, tokens, or authorization data.
7. Call `GET /audit-review-reports/{report_id}` again and confirm report status, score, rating, findings, and approval metadata are unchanged.
8. Optionally call `DELETE /audit-review-reports/{report_id}/ai-summary` and confirm only the AI summary fields are cleared.
9. Disable AI configuration and confirm generation returns the controlled `AI summary service is not configured.` response.
10. Parse `Veeva_Audit_Review_Module.postman_collection.json` and run the Step 11 Postman requests.

## Human Review Requirement

AI output is advisory. QA/Compliance reviewers must verify all AI narrative against deterministic checks, score rows, findings, and approval metadata before using any wording in controlled documentation.
